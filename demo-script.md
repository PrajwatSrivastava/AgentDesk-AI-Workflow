# Agent Desk: demo video script

**Length:** 2 min 28 s · **Format:** screencast of the live app with motion graphics, word-by-word captions and a gentle lo-fi backing track · **Voice:** energetic, friendly, quick but clear

**One-line pitch (the first 10 seconds):** describe any job in plain English and get a reliable AI workflow that does it.

**Demo request used on screen:** "Give me 5 fellowship deadlines related to AI safety."

**Look:** 60-30-10 colour, in the style of Linear and Vercel launch videos. 60% is a near-black base (`#07080C`) with glass panels. 30% is the app's own indigo-to-violet (`#5C6FF0` → `#8B5CF6`), used only as soft glows. 10% is one coral accent (`#FF7A59`), kept for focus: the highlight ring, the spoken word in the captions, stickers and the "Try it now" button. Green and red appear only for success and failure.

**Motion design (version 3):** one line-icon set throughout (no emoji), and a fixed set of moves, each used for one job:

| Move | Used for |
|---|---|
| Rise / blur-in | Headline words, titles, cards, the app window's entrance |
| Pop / pop-bold | Stickers and badges; the word or chip being spoken bumps in coral |
| Punch-in | Logo slam, chapter numbers, the "Rejected!" stamp (with a screen shake), a micro-zoom on every click |
| Typewriter | The request bubble, the JSON plan, "INTRODUCING", the closing URL |
| Count-up | 5 pages → 11 records → 5 deadlines, 6/6 steps, 42 technologies |
| Checklist tick | Test-run steps, identical runs, each fellowship in the result |
| Bar fill | Pipeline connector, compile progress, stat bars, chapter underlines |
| Reframe | The camera eases between parts of the app as they're named |
| Launch stinger | Each chapter opens with a big outlined number and title, which then tucks into the corner label |

**Transitions:** blur-dissolve, zoom-through, whip-pan, vertical push, diagonal stripe-wipe (indigo, violet, coral, ink), iris and light-sweep, each used once or twice so no cut repeats back to back.

## 1. Hook (0:00–0:08)

**On screen:** dark animated background. "Describe any job" pops in word by word, then "in plain English" with an underline sweep. A chat bubble with the request appears, and four step chips stack beside it (Search the web → Extract records → Clean the list → Post to Notion). On "Meet", the Agent Desk logo slams in with a flash and the chips glide into a pipeline row beneath it.

**Say:**
> What if you could describe any job in plain English, and get an AI workflow that actually does it? Meet Agent Desk!

## 2. The idea (0:08–0:23)

**On screen:** split screen. On the left, "Typical AI agent" with a wobbly path and three runs that come out differently. On the right, "Agent Desk": a JSON plan is written once, a straight rail of steps lights up, and three identical ✓ runs stamp in. On the last line, "Readable · Testable · Reliable" pop in as badges.

**Say:**
> Most AI agents improvise, every single time. Agent Desk is different. Nebius plans the workflow once, and then a deterministic engine runs it exactly the same way, every time. Readable, testable, reliable.

## 3. The team of agents (0:23–0:32)

**On screen:** the app's home page flies in inside a browser frame. The camera zooms to the agent grid and the cursor clicks **Personal Assistant**.

**Say:**
> Every account starts with a team of six ready-made agents, from a Personal Assistant to a News Monitor, each with skills you can switch on.

## 4. A vague request (0:32–0:40)

**On screen:** zoom into the chat. The request is typed live: *"Give me 5 fellowship deadlines related to AI safety."* Send.

**Say:**
> Let's give the Personal Assistant a job, and keep it vague: give me five fellowship deadlines related to AI safety.

## 5. It asks back (0:40–0:58)

**On screen:** the questions card appears ("Here's what I understood…"). Each question is highlighted as it's discussed. The cursor picks **Both open and recently closed ones**, **Notion** and **Every week**, leaves **No, send it automatically**, and clicks **Build it**.

**Say:**
> Instead of guessing, it asks me back! Only open fellowships, or recently closed ones too? I'll take both, to plan for the next round. Where should results go? Notion. How often? Every week. The best guesses are pre-picked, so it's just a few clicks, and Build!

## 6. The compiled workflow (0:58–1:13)

**On screen:** "Nebius is compiling…" shows, then the six-step draft slides in. Each step is highlighted in turn with a sticker:

| Step | Sticker |
|---|---|
| Tavily: search | Web search |
| Filter on the search count | Skip if empty |
| Ask the model for records | AI → records |
| Data: tidy list | Plain code, no AI |
| Filter on the tidy count | Only if found |
| Notion: append to page | Notion |

**Say:**
> Nebius compiles a six-step workflow. It searches the web with Tavily, pulls out each fellowship as a structured record, then cleans the list in plain code: no duplicates, only upcoming deadlines, sorted, and formatted for Notion.

## 7. Save (1:13–1:20)

**On screen:** click **Save this skill**. The **Test run** button is highlighted with a "Ready to run" sticker.

**Say:**
> One click saves it as a skill. Every app it needs is already connected, so it's ready to run.

## 8. Test run (1:20–1:30)

**On screen:** click **Test run** ("Fetching real data…"). Every step turns ✓, the status reads **Succeeded**, and confetti bursts. Notion shows "suppressed in test run".

**Say:**
> Now the best part: a test run! It fetches real data, but never sends a thing. Seconds later, every step reports back.

## 9. The result (1:30–1:45)

**On screen:** the tidy step opens. A Notion-style card slides in with the real fellowships from the run, with a counter reading "5 pages → 11 records → 5 deadlines". Then the AI step opens to show the **exact prompt sent** to the model.

**Say:**
> And there it is: real AI safety fellowships with their deadlines, de-duplicated, sorted and formatted, ready for Notion. Every step is fully inspectable: what went in, what came out, even the exact prompt sent to the model.

## 10. Connections you can trust (1:45–1:59)

**On screen:** the Connections page (Tavily, Resend and Notion connected; keys hidden). A fake Slack webhook is typed and saved, and it's refused with a red error and a "Rejected!" sticker.

**Say:**
> Connections are set up once, and shared by every agent. Each key is checked against the real service before it's saved, then stored encrypted. A fake Slack webhook? Rejected, on the spot!

## 11. And more (1:59–2:07)

**On screen:** feature chips fly in as each is named: ✋ Approval steps · ⏰ Schedules · 🔗 Webhooks · 📊 Daily run limits. On "dark mode", a circle wipe turns the app from light to dark.

**Say:**
> And there's more: approval steps that wait for your OK, schedules, webhooks, daily run limits, and yes, dark mode!

## 12. How it's built (2:07–2:19)

**On screen:** "Built with", with a count-up to "42 technologies · 7 groups". Seven glass cards rise in, each with a line icon, holding all 42 technologies. Each item the voice names glows coral as it's spoken and keeps a coral outline. The wall holds for about 4 seconds after the line, so it can be read.

| Group | Technologies |

| 🤖 AI | Nebius Token Factory · DeepSeek V4 (compiler) · Qwen3 (AI steps) · JSON-schema output |

| 🌐 Web data | Tavily search · Jina Reader · cheerio · fast-xml-parser · robots.txt aware |

**Say:**
> It's built with Next.js, Nebius, Neon Postgres, Tavily and Jina Reader, and it's live on Vercel.

## 13. Close (2:19–2:28)

**On screen:** Agent Desk logo, the tagline "Plain English in. Reliable workflows out." and the live link **agent-desk-ai-workflow.vercel.app** with a pulsing "Try it now →".

**Say:**
> Agent Desk. Plain English in, reliable workflows out. Go try it now!

## Recording notes

- **Order of the story:** pitch first, then one complete flow (ask → questions → build → save → test → result), then trust (connections), then breadth (features and stack), then the link. The judges see the whole product working on real data within 90 seconds.
- **Real data only:** every result on screen comes from a live run. If you re-record, the fellowships found will differ; that's fine.
- **Privacy:** keys and the account email are hidden before anything is shown.
- **If you record it yourself:** do a dry run first. Use "both open and recently closed" on the card so the test run is guaranteed to have results. Keep the cursor still while you talk, and cut the waiting time while it compiles.
- **Upload early:** processing on YouTube or Vimeo can take hours.
